# กฎของโดเมน — สิ่งที่เรียนรู้มาด้วยราคาแพง

ทุกข้อในไฟล์นี้เคยผิดมาแล้วจริง หรือเป็นจุดที่เครื่องคิดเลขทั่วไปผิด
แต่ละข้อมี test vector (TV-xx) ตรึงไว้ ดูรายการเต็มที่ [test-vectors.md](test-vectors.md)
ในโค้ดข้อเหล่านี้มักมีคอมเมนต์ ⛔ กำกับ — **อ่านคอมเมนต์ ⛔ ก่อนแก้ทุกครั้ง**

## เงินและตัวเลข

- เงินเป็น bigint สองชั้น: `Satang` (สตางค์ ใช้เก็บ/แสดง) และ `Fixed` (×10¹² ต่อสตางค์ ใช้ระหว่างคำนวณ)
  เหตุผล: ดอกรายวันหารไม่ลงตัว ถ้าปัดทุกวันเศษจะสะสมผิดทั้งงวด
- ห้าม float กับเงินเด็ดขาด อัตราเป็น bps
- **แสดงสตางค์ทุกช่องเสมอ** — `bahtRounded` ถูกลบไปแล้ว ห้ามใส่กลับ ห้ามส่ง `0` ทศนิยมเข้า
  `baht` / `bahtFixed` / `bahtNumber` (TV-54 สแกนซอร์สจับ) [SOURCE: ผู้ใช้ "เรื่องเงินทอง ไม่ต้องซ่อนทศนิยม"]
  ยกเว้นที่ตั้งใจ: ป้ายแกนกราฟ, เพดานภาษี 100,000 ในประโยค, ช่วงค่าธรรมเนียมโดยประมาณ
- ห้ามเฉลี่ยอัตราดอกเบี้ยแบบเลขคณิต ต้องถ่วงด้วยเงินต้นและจำนวนวัน (TV-27)

## วันที่

- civil date `'YYYY-MM-DD'` ล้วน ⛔ ห้าม `Date` ของ JS ใน engine (timezone ทำวันเลื่อน)
- ปีใน UI เป็น พ.ศ. แปลงที่ `format.ts` ที่เดียว DB/engine/test เป็น ค.ศ. เสมอ
- **anchor ของวันตัดคงที่** นับจาก `first_due_date` ไม่นับต่อจากวันตัดจริงของงวดก่อน
  ไม่งั้นวันตัดไหลจากวันที่ 5 ไปถึงวันที่ 1 ใน 30 ปี (TV-32, TV-0)
- override วันตัดรายงวดต้องไม่ทำให้งวดถัดไปขยับ (TV-31, TV-33)
- `date_roll = preceding` = ขยับมาเร็วขึ้น มีอยู่จริงในสัญญาไทย (TV-29)
- ปฏิทินวันหยุดธนาคารต้องเติมปีต่อปี (วันพระ/ชดเชย/ครม. ประกาศ คำนวณล่วงหน้าไม่ได้)
  ปีที่ไม่มีข้อมูล fallback เป็นเสาร์-อาทิตย์ — **ปีที่ยังไม่ได้ seed ตารางจะเพี้ยนเงียบ ๆ** (TV-0 เคยพังเพราะปี 2568 ไม่มีปฏิทิน)

## ดอกเบี้ย

- ดอก = เงินต้นคงเหลือ × อัตรา ÷ ตัวหารตาม basis × **วันจริง** ⛔ ห้าม `/12`
- day-count 3 แบบ `ACT/365F` (default) / `ACT/ACT` (ตัดช่วงที่ขอบปี) / `ACT/365_SKIP` — เป็น config ต่อสัญญา
  และ effective-dated (`loan_conventions`) เพราะธนาคารเปลี่ยนกลางสัญญาได้
- **ช่วงคิดดอกของงวด = (วันตัดงวดก่อน, วันตัดงวดนี้]** — รวมวันตัด ไม่รวมวันเริ่ม
  จำนวนวัน = `daysBetween(from, due)` ป้ายบนจอและรายงานต้องเขียนแบบนี้ให้ตรงใบแจ้งยอด (TV-50)
  หมายเหตุ: ข้างใน `accrual.ts` วนเป็นช่วงครึ่งเปิด `[d0, d1)` ได้จำนวนวันเท่ากัน — คอมเมนต์หัวไฟล์นั้นพูดถึงรูปแบบภายใน
- อัตราเปลี่ยนกลางงวดต้องแบ่งเป็นท่อน ห้ามใช้อัตราเดียวทั้งงวด (TV-7)
- ปัดเศษ **ครั้งเดียวต่อหนึ่งจุดตัดชำระ** สะสม exact ระหว่างทาง
- จ่ายไม่พอดอก: default ยกเป็นดอกค้างไม่ทบต้น (ป.พ.พ. ม.655) หรือทบต้นถ้าตั้งไว้ (TV-3)

## การจ่ายจริง

- **ธนาคารตัดดอก ณ ทุกวันที่เงินเข้า** ดอกก่อน ที่เหลือเข้าเงินต้น — จ่ายวันที่ 3 แล้วโอนเพิ่มวันที่ 5
  คือ 29 วันบนยอดเต็ม + 2 วันบนยอดที่ลดแล้ว ไม่ใช่รวมไปตัดทีเดียววันที่ 5 (TV-51, ยืนยันจากสลิปจริง)
- ประเภทการจ่ายบอกว่า **ธนาคารเอาเงินไปทำอะไร** ไม่ใช่ว่าเราตั้งใจอะไร
  - `installment` ตัดดอกที่ค้างถึงวันนั้นก่อน — ใช้เมื่อสลิปมีบรรทัด "ยอดดอกเบี้ยที่ชำระ" แม้โอนเกินค่างวด
  - `partial_prepay` ตัดเงินต้นเต็มจำนวน ไม่หักดอก
  - `full_redemption` ปิดบัญชี ตารางจบที่งวดนั้น
  - `fee` ไม่ตัดหนี้
  - ⛔ โอนรวมค่างวด+โปะก้อนเดียว = บันทึก **รายการเดียว** บันทึกสองรายการหนี้จะลดซ้ำ
- ยอดจ่ายจริงแทนค่างวดตามสัญญาของงวดนั้น (TV-35)
- งวดที่อยู่ก่อนรายการล่าสุดแต่ไม่มีบันทึก = **ไม่ได้จ่าย** ไม่ใช่ยังไม่ได้กรอก (TV-47)
  ⛔ ห้ามใช้ "วันนี้" เป็นเส้นแบ่ง — คนที่หยุดกรอกครึ่งปีจะกลายเป็นค้างชำระ 6 งวด
- "ผ่อนไปกี่งวด / เหลือหนี้เท่าไหร่ วันนี้" นับงวดที่จ่ายแล้วจริงด้วย ไม่รอวันครบกำหนด (TV-39)
- `payments` ห้าม hard delete — soft delete ด้วย `deleted_at` ไม่งั้นงวดที่เคยกระทบยอดตรงจะเปลี่ยนเงียบ

## แผนโปะ

- เก็บเป็น 12 เดือน + override รายปี + โหมดทำซ้ำ ⛔ ไม่ใช่ array 360 ช่อง
- ยอดโปะตามแผนลง **ณ วันตัดงวด** เสมอ
- **ความจริงชนะแผน** — งวดที่มีรายการจ่ายบันทึกไว้ หรืออยู่ก่อนรายการล่าสุด แผนไม่ลงให้เลย (TV-55)
  เคยพัง: เดือนที่มีทั้งแผนและยอดโปะจริง ตารางลงทั้งสองก้อน ตัดหนี้เกินเงินที่จ่ายจริง
  ผิดเดือนเดียวแต่วันปิดหนี้เร็วไปหลายปี
- คอลัมน์ "โปะ" ใช้ `prepayOfRow` ตัวเดียวทั้งแอพ (ตาราง, ปฏิทิน, รายงาน, CSV)
  ⛔ ห้ามอ่าน `r.prepayFixed` ตรง ๆ — ไม่นับเงินที่โอนเกินค่างวดในรายการ `installment` (TV-49, TV-52)
- เงินโปะของแผน = ส่วนต่างจากเส้นฐาน ไม่ใช่ยอดสะสมรวมสิ่งที่จ่ายไปแล้ว (TV-43)
- "ประหยัดดอกไปแล้ว" ตัดที่งวดเดียวกันทั้งสองฝั่ง ไม่ใช่ลบยอดรวมทั้งสัญญา (TV-44)
- เคยมี "โปะก้อนตามวันที่" (lumps) — **ถอดออกแล้ว ห้ามใส่กลับ** นับเฉพาะเมื่อวันตรงวันตัดเป๊ะ
  ไม่ตรงถูกทิ้งเงียบ ๆ การโปะจริงให้บันทึกเป็นรายการจ่าย [SOURCE: ผู้ใช้]
- ROI ของการโปะ **ลดลง** เมื่อโปะหนักขึ้น ต้องแสดง diminishing return

## ภาษี

- เพดานลดหย่อนดอกเบี้ยบ้าน **100,000 บาทต่อคนต่อปี** ไม่ใช่ต่อสัญญา — คิดรวมทุกสัญญาเสมอ (TV-30)
- ใช้ปีปฏิทิน (TV-26) อัตราภาษีส่วนเพิ่มผู้ใช้กรอกเอง ⛔ ไม่กรอก = ไม่เดา ช่องเป็นขีด
- คำแนะนำที่ให้ผู้ใช้ไปแล้ว: การคงหนี้ไว้เพื่อรักษาสิทธิ = จ่ายดอก 1 บาทเพื่อได้ภาษีคืน 10–35 สตางค์ ขาดทุนเสมอ
  แอพแสดงผลกระทบต่อสิทธิเป็นข้อมูลประกอบ ไม่ใช่เป้าหมายให้ไปจูน

## สัญญา

- ค่างวดต่างกันตามช่วงได้ (ปี 1/2/3/หลังพ้นโปร) เก็บบนแถวเดียวกับขั้นอัตรา (TV-41)
  "ค่างวดตามสัญญา" เว้นว่างได้เมื่อกรอกครบทุกช่วง (TV-42)
- ค่างวดไม่พอจ่ายดอกหลังพ้นโปร = หนี้ไม่มีวันหมด → เตือนที่หน้าสัญญาและบอกช่องที่ต้องตรวจ
  ห้ามรายงานว่า "เร็วขึ้น 73 ปี" ซึ่งเทียบกับเพดานจำนวนงวด (TV-44, TV-46)
- แก้สัญญา ⛔ ห้ามลบแล้วสร้างใหม่ — cascade ลบ payments ทั้งหมด ต้องแก้ทับทีละตาราง
- **ปิดสัญญา = ป้ายสถานะอย่างเดียว** ไม่ลบอะไร กดเปิดกลับได้ (TV-53)
  - ตัดตารางที่วันปิดด้วย `rowsUntilClose` ทุกหน้า รวมทั้งตาราง "ถ้าไม่โปะ"
  - ไม่นับเข้าหนี้รวม แต่ดอกที่จ่ายก่อนวันปิดยังเข้าสิทธิลดหย่อนปีนั้น
  - ปิดล่วงหน้าไม่ได้ ปิดก่อนวันเบิกไม่ได้ มีรายการจ่ายหลังวันปิดไม่ได้
  - ⛔ ห้ามแก้ `origin` ของสัญญาใหม่ตอนปิด — ค่าเดิมไม่ได้เก็บไว้ เปิดกลับแล้วคืนไม่ได้

## เปรียบเทียบ / รีไฟแนนซ์

- จัดอันดับด้วย **ค่างวดเท่ากันทุกธนาคาร** (equal payment) — ค่างวดไม่เท่า = เทียบกระแสเงินสดคนละชุด (TV-11)
- รวมค่าธรรมเนียม ประกัน MRTA ⛔ ห้ามบวกรายการที่ `is_financed` ซ้ำ เพราะอยู่ในเงินต้นแล้ว (TV-17)
- รีไฟแนนซ์เทียบ 3 ทางเสมอ มี "อยู่เฉย ๆ" เป็น baseline
- กับดักยืดเทอม: "ค่างวดลด 2,500/เดือน" อาจจ่ายดอกรวมมากขึ้น ต้องเตือน (TV-18)
- ค่างวดใหม่ต่ำกว่าดอก → ตีตก ไม่โชว์เป็นทางเลือก (TV-34)
- ⛔ ห้าม seed อัตราโปรโมชั่นรายผลิตภัณฑ์ — เปลี่ยนทุกเดือนและขึ้นกับ LTV จะกลายเป็นเลขปลอมแปะชื่อธนาคารจริง

## รายงานที่ส่งออก (HTML)

- escape ข้อความผู้ใช้ทุกจุด (ชื่อทรัพย์สิน, หมายเหตุ) — ไฟล์ถูกส่งต่อทางแชท (TV-52)
- ⛔ ห้ามอ้างไฟล์ภายนอก ต้องเปิดได้ตอนไม่มีเน็ต
- `rows` ต้องถูกตัดที่วันปิดมาก่อน รายงานไม่ตัดเอง
