## การตัดสินใจที่สำคัญ

| เรื่อง | ตัดสินใจ | เพราะ |
|---|---|---|
| เงิน | bigint สตางค์ + Fixed ×10¹² | ดอกรายวันหารไม่ลงตัว float สะสมผิด |
| คำนวณที่ไหน | ในเบราว์เซอร์ทั้งหมด ไม่มี backend | free tier, ออฟไลน์ได้, engine ทดสอบได้ล้วน |
| Supabase | ใช้ project ร่วมกับอีกแอพ แยก schema `ponwai` | free tier จำกัด 2 project |
| Hosting | Pages เป็น URL หลัก + เก็บ Worker ไว้ | Pages ไม่มี cron · URL Pages ไม่มีชื่อ account |
| `.env` | commit ได้ | มีแต่ publishable key ซึ่งฝังใน bundle อยู่แล้ว · CI build ได้โดยไม่ตั้งตัวแปรเพิ่ม |
| ช่วงคิดดอก | ป้าย (วันตัดก่อน, วันตัดนี้] | ใบแจ้งยอดเขียน "คิดดอกถึงวันที่ 5" — ผู้ใช้แย้งจนพบว่าป้ายเดิมเลื่อนไปหนึ่งวัน |
| ยอดจ่ายก่อนวันตัด | ตัดดอก ณ วันที่เงินเข้า | ยืนยันจากสลิปจริง ผลต่าง 3.13 บาท = ดอก 2 วัน |
| ธนาคารต่างกัน | ให้เลือกประเภทการจ่ายจากสลิป ไม่ใช่ให้แอพเดา | แต่ละธนาคาร/ช่องทางตัดไม่เหมือนกัน |
| โปะก้อนตามวันที่ | ถอดออก | ทิ้งยอดเงียบ ๆ ถ้าวันไม่ตรงวันตัด และซ้ำกับปฏิทิน + บันทึกการจ่าย [ผู้ใช้สั่ง] |
| ตาราง `prepay_lumps` | เก็บไว้ ไม่ drop | ข้อมูลเก่าหาย |
| ปิดสัญญา | ป้ายสถานะอย่างเดียว กดกลับได้ | ปุ่ม "ลบ" cascade ลบประวัติการจ่าย และผู้ใช้ขอให้ revert ได้ |
| ทศนิยม | แสดงสตางค์ทุกช่อง | [ผู้ใช้สั่ง] "เรื่องเงินทอง ไม่ต้องซ่อนทศนิยม" |
| แผน vs จ่ายจริง | ความจริงชนะแผนเสมอ | แผน + จ่ายจริงเคยถูกลงซ้อนกันในเดือนเดียว |
| คำแนะนำภาษี | โปะเร็วดีกว่ารอ · ไม่ควรจูนหนี้ให้ชนเพดานพอดี | คงหนี้ 1 บาทได้ภาษีคืน 10–35 สตางค์ |

## เหตุการณ์ที่ควรรู้

- **TV-0 (2026-09-25)** — งวดแรกไม่ตรงใบแจ้งยอดมี 4 ชั้นซ้อนกัน: `first_due_date` เก็บแต่ไม่เคยถูกอ่าน,
  ปฏิทินวันหยุดไม่มีปี 2568, ป้ายช่วงคิดดอกเลื่อนหนึ่งวัน, engine รวมยอดจ่ายไปตัดที่วันตัดแทนวันที่เงินเข้า
  แก้ครบแล้วผู้ใช้ยืนยันว่า "ตรงหมดแล้ว"
- **CI แดง 3 commit (ab94543 → 2cefb8d)** — `_redirects` ใน `public/` ทำให้ `wrangler deploy` ตาย
  ระหว่างนั้นเว็บไม่อัปเดตเลยโดยไม่มีใครรู้ — ทุกครั้งที่ "เว็บไม่อัปเดต" ให้ดู `gh run list` ก่อน
- **คอลัมน์โปะว่าง** — อ่าน `r.prepayFixed` ตรง ๆ ไม่นับยอดที่โอนเกินค่างวด เกิดซ้ำสองครั้ง (ตาราง แล้วรายงาน)
  จึงมี `prepayOfRow` เป็นตัวเดียว และ TV-49/TV-52 ตรึงไว้
- **Dashboard กับหน้าสัญญาบอกวันปิดหนี้ต่างกัน** — Dashboard ไม่ได้ใส่แผนโปะ → กฎ "ทุกหน้าเดินเส้นเดียวกัน"
- **แผน + จ่ายจริงซ้อนกัน (TV-55)** — ตารางตัดหนี้เกินจริงในเดือนเดียว ลามจนวันปิดหนี้ผิดไปหลายปี

## คนที่เกี่ยวข้อง

- ผู้ใช้ / เจ้าของโปรเจกต์ใช้แอพกับสัญญาจริงของตัวเอง ฟีดแบ็กส่วนใหญ่มาจากการเทียบกับใบแจ้งยอดและสลิป
- ทำงานผ่าน Claude Code — ผู้ใช้สื่อสารภาษาไทย ชอบคำตอบที่มีตัวเลขยืนยัน และสั่งเอาของที่ทำให้สับสนออกได้เลย
