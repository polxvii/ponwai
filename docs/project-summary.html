กฎที่ห้ามละเมิด

ทุกข้อเคยพังมาแล้วจริง เหตุผลเต็มอยู่ใน docs/domain-rules.md และคอมเมนต์ ⛔ ในโค้ด

ความปลอดภัย (repo เป็น public)

  • Supabase secret / service_role key ห้ามอยู่ใน .env ห้ามแปะในแชท ห้าม commit
  • credential อื่นอยู่ .env.local เท่านั้น — ห้ามแปะรหัสบัญชีทดสอบในแชท
  • ห้ามใส่ตัวเลขสัญญาจริงของผู้ใช้ลง repo ใช้ตัวเลขสมมติ
  • Service worker ห้าม cache request ไป Supabase

ข้อมูล

  • payments ห้าม hard delete — soft delete ด้วย deleted_at
  • แก้สัญญาห้ามลบแล้วสร้างใหม่ (cascade ลบประวัติการจ่าย)
  • ห้าม drop prepay_lumps · ห้ามให้ลบวันหยุดของกลาง · reference_rates แก้ไม่ได้
  • _redirects อยู่ deploy/pages/ เท่านั้น

ตัวเลข

  • เงิน bigint · อัตรา bps · ห้าม float · ดอกรายวัน ห้าม /12
  • วันที่ 'YYYY-MM-DD' ห้าม Date ใน engine · UI แสดง พ.ศ.
  • แสดงเงินมีสตางค์ทุกช่อง · คอลัมน์โปะใช้ prepayOfRow
  • ความจริงชนะแผนโปะ · ช่วงคิดดอก (วันตัดก่อน, วันตัดนี้]
  • เพดานลดหย่อน 100,000 เป็นของคน รวมทุกสัญญา

ย้าย account — ย่อ

ขั้นตอนเต็มทีละบริการ: docs/account-migration.md

ก่อนเริ่ม

  1. ส่งออก "รายงานฉบับเต็ม" + CSV การจ่ายของทุกสัญญาเก็บไว้
  2. ใช้เป็นตัวเทียบหลังย้ายว่าตัวเลขตรงทุกสตางค์

Supabase (ยากสุด)

  1. ถ้าทำได้ transfer project ไป org ใหม่ — ไม่ต้องแก้อะไรเลย
  2. ไม่ได้: migrations → ⚠️ ไม่รัน seed ถ้า restore ข้อมูลเต็ม → expose ponwai → Auth URLs
  3. dump/restore schema ponwai แทน user id เก่าด้วยใหม่ก่อน restore
  4. แก้ .env + Worker vars

ตรวจหลังย้าย

  1. ล็อกอินได้ทั้ง password และ Google
  2. สัญญาครบ ตัวเลขตรงรายงานที่ส่งออกไว้
  3. CI เขียว · deep link ไม่ 404
  4. Worker log เห็น keep-alive: 200
